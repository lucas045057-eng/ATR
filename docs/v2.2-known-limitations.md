# ATR V2.2 限制与后续

V2.2 代码和可独立验收项已完成；以下能力没有被此次结果证明，不能以测试通过替代真实验收。

## 尚未验证

- 真实模型供应商：未提供显式启用和有效凭据，未搜寻 Key。LiteLLM HTTP 用本地假服务，调查使用 Stub。JSON/usage/超时/预算的工程验证不是模型智能或真实账单验证。
- 真实业务 Linux/SSH/systemd 权限：只验收本机隔离 OpenSSH 夹具。真实账号、网关、目录及主机公钥必须由服务器所有者审核。本次未连接或修改生产服务器。
- Windows Docker Desktop Linux 引擎未能启动；使用现有 WSL Linux Engine 实测。WSL 原生 uv API 启动未直接运行，GitHub Actions 未远端运行。
- 完整十类真实基础设施故障集：原 A/B 的 MySQL/PostgreSQL/Nginx 与恢复是真实容器；新增 store/cache/edge 为 Python TCP 测试替身。13 个案例的比较为 Docker 观测经 Mock 重放 + Stub，不是端到端真实 SSH+模型或生产正确率。

## 当前能力边界

- Gate 因果最低机制只有 startup_failure、permission_denied、bind_failure、database_unavailable、redis_unavailable。上游、端口错配、错误依赖和未知机制通常 unresolved；源码、日志 ERROR 数量、模型置信度、历史 Pattern 均不能替代当前因果证据。
- supported 表示一个可能原因通过最低核验，不是完整根因证明。多服务故障以首个支持假设停止，可能只覆盖部分原因；评测单列部分诊断，未冒充完整正确。
- 这个 Stub 集上 Adaptive 完整正确率与 Graph-only 相同，模型/上下文成本更高；没有证据支持准确率提升。Pattern 固定基线的角色收窄会漏查依赖，未解决率更高。
- 原 Collector 路线保留固定流程；Adaptive 需要已审核业务画像和当前绑定。UI 支持三臂展示，写入第三臂通过 API/评测脚本；原两臂表单不变。
- 单 API 进程、SQLite 和本地线程池；无多进程 Worker 协调、多租户/RBAC、跨主机任务队列、调查取消或自动修复。重启明确中断正在进行的任务，不悄悄续跑已预留模型调用。
- 名称发现不是全集：扫描最多 2,048 行/1 MiB/8 秒，进程 comm 受 Linux 原生命令 15 字符限制。动态 PID 集变化时分页不是事务快照；超时/部分结果不能证明不存在。定向发现仍需准确线索及人工确认。
- 授权状态与当前性分离。发现失败保留授权，但过期事实不用于调查。直接手工只读入口使用原确认授权；Adaptive 执行前另查绑定当前性。
- Pattern 兼容按资料/部署摘要和服务集合保守判断，可能阻止无害变更；旧源快照缺失则拒绝复用。失效反馈保留旧 Trusted 审核史但停止建议，需新的验证 Candidate，不会自动修复或重授信。
- 非标准评测真值依赖操作者评分；标准 truth 只保证与登记标签一致，不能证明标签本身正确。两次重复是可重复性检查，样本量不足以估计真实模型泛化表现。
- token 上界为 UTF-8 字节估算；Stub 无供应商 usage，费用未知。真实服务回传 usage 时标 actual，但费用仍按配置费率估算。LiteLLM 有一项事件循环 DeprecationWarning。
- 保留 V2.1 的有限 Python AST/JS/TS 骨架、人工图片/PDF 录入和本地检索，未新增完整语言语义、自动视觉理解或生产准确率承诺。

Docker Collector 具有宿主 daemon 能力，socket 的 :ro 挂载不是生产安全边界；本次只在隔离 Demo 启用，验收结束停止该 Collector。数据库、Volume、上传资料、历史及配置均保留。

## 下一版本建议

1. 由操作者明确提供真实模型测试授权与预算，在相同冻结案例上测量 usage、费用与诊断质量；保留所有失败，不调整 Gate 来提高成功率。
2. 用真实隔离 systemd 服务、Redis/Nginx 以及配置端口/依赖故障补齐夹具；实现异常组和多故障覆盖停止条件，同时保持证据要求。
3. 将新增机制规则与预测字段逐项校准，测试现象/机制/深层原因的区分；加入时钟偏差提示，保留原事件时间，不改写日志。
4. 根据真实知识反馈调整检查排序，支持新的人工审核 Pattern 版本、兼容差异解释和第三臂 UI 录入。
5. 有实际多进程需求后再设计持久 Worker 协调/可审计取消；在此之前保持单进程，避免引入额外基础设施。
