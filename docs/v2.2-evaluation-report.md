# V2.2 故障评测（Phase 5）

2026-10-09，13 个案例 × 3 模式 = 39 次已完成调查。原始记录：[JSON](verification/v22-fault-evaluation.json)。

运行范围：隔离 Docker 中真实 Python 进程、socket 连接拒绝/重复 bind、非特权文件权限；状态和原始日志在取样后通过 MockConnector 重放。模型是只读观察驱动的确定性 Stub，无真实供应商调用。store/cache/edge 为 Python TCP 测试替身，不能代表完整 MySQL/Redis/Nginx。原 A/B 的真实 MySQL/PostgreSQL/Nginx 故障验收另见 [记录](verification/v22-docker-demos.json)。

每组三臂使用同一图版本、模型/预算配置、原始观测和故障窗口。窗口以故障宿主的容器创建时间为起点，不改日志时间。初轮 Windows/WSL 时钟差的记录保留在 v22-fault-evaluation-initial.json，不纳入下表。Trusted Pattern 为单独合成训练案例，经原人工修复声明、真实 loopback HTTP 200、审核 API 生成；它只提供检查建议。

这个测试集没有显示 Adaptive 正确率提升。它在相同机制核验下减少部分工具读取，但增加多轮模型/上下文成本。Pattern 的应用角色收窄导致依赖故障未解决。多服务同时异常的 Gate 以首个满足最低条件的假设停止，尚未确保完整故障集合。未知上游/端口/依赖机制被保守拒绝；健康 ERROR 与历史日志没有被确认成根因。

重跑：在锁定开发环境运行 scripts/evaluate_faults.py，指定新的 --work-dir 与 --output；真实容器取样加 --docker 或 --docker-wsl Ubuntu 和 --allow-isolated-mutations。仅创建带 atr.v22.evaluation=isolated 的专用无网络、只读、非特权容器；结束删除新夹具容器，不创建或删除 Volume。已有评测数据库拒绝覆盖。

此报告是工程行为/成本测量，不能作为生产准确率、真实模型能力或延迟承诺。
