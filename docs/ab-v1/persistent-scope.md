# 持久业务授权与自主只读调查（P0.5）

业务对象授权和运行观测分别保存。`service_bindings.authorization_json` 保存原 SSH Target 授权摘要、确认人、确认时间和精确身份规则；不按时间自动撤销。`observed_at`、`expires_at`、`freshness_status` 仍表示短期身份观测，不能作为历史正常状态的复用许可。Evidence Gate 的事故窗口、启动身份、独立证据和反证检查保持不变。

schema 28 只新增授权元数据、每次调查的身份验证标记和 `investigation_defaults`。迁移前创建一致数据库备份；原确认映射只迁移为原实例的 `exact_instance` 授权，不自动批准替换实例。原调查与证据不删除。

每个新的 `ab_v1` 调查冻结目标、资料版本、授权摘要和默认服务范围，先执行相关只读清单工具，再验证当前实例。核验通过后接入原 P0 基础采集、AI、多轮调查、模型失败离线流程和确定性报告。每次工具/模型操作前后重新检查授权；调查中撤销授权会停止后续操作，迟到读取不成为证据。历史 `waiting_input` 调查与其他授权功能仍可使用原 Coordinator 接口。

身份规则：

- `exact_instance`：实例 ID 和完整候选身份摘要相同。
- 人工批准的 `stable_object`：容器的名称、镜像标识、端口和环境变量键集合相同；系统服务另要求服务 ID 相同。多个实例同时满足规则时视为冲突，跳过读取。
- 进程只允许精确 PID、主机启动身份和进程启动身份；不按进程名自动接续。
- 模型、名称相似度与资料匹配只能产生线索，不能批准对象。

发现未知对象后保存清单来源，在独立审核区域展示。未授权对象不读取详细状态/日志；原授权调查继续。没有通过验证的对象时有限结束为 `unresolved`，释放 Worker；无需等待操作者回复。多个目标优先使用操作者保存的默认目标，默认目标不可用不会自动回退。默认服务只能是该目标已有授权的服务。

操作者接口：

- `GET /api/v1/businesses/{id}/bindings`：分别展示授权有效性、观测有效性和审核历史。
- `POST .../bindings/{binding_id}/revoke`：撤销对应授权及接续实例。
- `PUT .../bindings/{binding_id}/authorization`：基于当前发现证据明确批准身份规则。
- `POST .../targets/{target_id}/authorize-object`：依据实际、新鲜、目标配置未变化的 `observation_id` 独立批准对象。
- `GET/PUT .../investigation-defaults`：设置已授权目标、服务范围和主服务。

日常页面一次提交故障即创建事件并启动 `ab_v1` 调查。阶段显示自动发现、身份验证、基础采集、AI 或离线调查。报告分别展示执行结果、模型状态、根因是否通过核验、直接异常和缺口；修复建议仅供人工评估。

仍需人工：首次目标/对象授权；新对象或身份变化、冲突；扩大访问范围；升级旧精确规则以允许替换实例；多目标默认范围的首次配置；失效 SSH 密码会话；任何写入、重启或修复审批。长期业务授权不会持久化密码，也不会提高 SSH 权限。

容器稳定规则必须实际取得镜像标识、端口和环境键字段；协议缺少这些字段时只允许精确实例授权，不能把“未采集”视为“空集合一致”。现有普通 SSH 和 forced gateway 的容器清单通常不提供完整字段，因此默认不会自动接续更换 CID 的容器。协议未提供的 Compose 标签或不可变镜像摘要不被宣称已经验证；本次不升级远端网关或提高读取权限。
