## 旧行为为何不收敛

调查循环先耗尽授权范围的基础候选，才检查是否完成；评价器又把数据库启动失败和代理上游不可用两段链作为全局必要条件。即使当前实例停止已足以说明它不能提供服务，仍会读取其他服务日志和配置。新证据 ID、时间与文本变化也容易被当作进展。

## 兼容字段与结果语义

复用 `task_type`，新 Run 在现有 `model_config_json` 冻结 `investigation_goal`，没有新增表或迁移：

| 现有任务类型 | 新 Run 的目标 | 完成含义 |
| --- | --- | --- |
| `focused_diagnosis` | `direct_fault` | 直接故障定位；触发原因可未知 |
| `root_cause_investigation` | `trigger_cause` | 当前适用因果主张通过独立证据核验 |
| `health_check` | `scoped_health` | 仅已执行检查范围未观察到故障 |

普通“API 未响应”默认直接定位；显式任务选择或“为什么退出、追查完整原因”等语义使用深入目标。页面显示本次目标。

`execution_status` 仍只表示执行生命周期。新增 `diagnosis_status=direct_cause_supported`，允许 `completion_satisfied=true`；它不等于 `root_cause_supported`，不获得修复验证、Trusted Pattern 或完整根因指标资格。指标单独保存 `direct_cause_runs` 和 `goal_completed_runs`。旧 Run 未冻结目标时保留原双链评价与已保存结果，不追溯改成成功。

结果使用 `direct_findings/direct_faults` 表示当前异常，`direct_explanations` 表示已解释的症状与实例范围，`trigger_cause_status` 区分未知和已验证，`impact_scope` 表示影响边界。报告先给结论、范围、依据和未知，完整证据审计可展开。

## 继续、完成与受阻

- 从明确命名服务、默认主服务、业务角色与当前授权绑定选择焦点；焦点缺失不得退到另一个服务。授权范围不再等于必须检查范围。
- 保留轻量身份发现，先相关实例状态；运行状态不能替代 API 入口检查。仅在当前连接错误指向实际关系时逐步扩展到依赖。缺映射时可读取消费者的已授权配置，关系未验证前不归因。
- 精确实例停止可独立确认，不强制要求日志；停止原因未知不会压住实例结论。多副本中的一个停止且入口正常，只报告实例异常，并明确结束这次检查。
- 入口影响需要更强证据：当前容器端口配置精确匹配本机授权 HTTP 入口，加上同一入口当前明确的连接拒绝。端口配置单独不证明独占承载，也不证明未被其他实例接管。负载均衡、远端入口或完整映射缺失时只报告已观测范围。
- 只核验适用主张；数据库与代理链保留为专用机制。没有代理的依赖启动故障可按独立已验证段确认。权限或绑定错误还要求当前启动／退出失败关系，普通请求错误不得冒充停止原因。
- 未注册故障允许保留模型候选、有效引用与可检验预测；置信度和引用本身不能升级因果关系。评估保留不适用、支持、反驳、证据不足和无法验证的区分。
- 每项检查保存问题、区分的解释、改变判断的结果。去重使用实际动作身份；进展按事实语义、必要缺口消除和已验证关系计算。发现新 ID、重复时间戳或配置目录本身不算根因进展。
- 模型失败保留现有事实，停止自动模型请求。工具失败保存安全类别、阶段、检查 ID；SSH、权限与模型能力错误不当业务原因。取消、后端恢复、单步期限和 180 秒无实际进展检测保留终态，拒绝迟到写入；预算继续 `accounting_only`。
- 页面 15 秒请求超时覆盖响应头和响应体；断网、悬挂、401/404 显示连接未知／具体错误并解锁新调查入口。恢复只读取原 Run，不自动重复 POST。

已执行真实 WSL Docker：仅创建本任务容器，`--pull=never` 使用已有 `python:3.12-slim`，显式随机本机端口 `55313`。运行时 GET 200；人工测试驱动停止后，同一容器为 `exited`，同一授权 URL 的生产 `health.get` 返回 `reachable=false, failure_kind=connection_refused`。原样观测回放评价器得到 `direct_cause_supported`、入口影响已验证、触发原因未知。测试容器已删除，无付费模型请求。

该验证是 Linux 直接运行生产函数，未经过真实 SSH 通道；helper 中 `remote_ssh` 是协议元数据，不代表本次实际用了 SSH。真实 SSH／外部模型端到端与生产部署尚未验证。旧“仅端口配置即可确认入口”的中间验证已被审查修正，不作最终验收依据。

完整 pytest、Ruff、构建与浏览器的最终数值见交付包中的 `verification.md`。初轮全量失败不被当作当前失败；现有后端失败另在原始基线隔离副本核对。
