## 实际隔离验收

**Docker/WSL：** Windows Desktop 引擎未能启动，使用现有 Ubuntu 24.04 的 Docker Engine 29.1.3 / Compose 1.29.2。API/UI 镜像、上传解析/索引 Worker、SQLite 实际运行；最终 API 2.2.0，API/UI 健康 200。重建/替换 API 后原业务画像、上传资料和索引逐对象相同。容器浏览器运行原完整接入断言及知识/三臂页面导航。专用端口 28000/28080；未操作其他业务容器或清理 Volume。

原 system-a/system-b 人工停止数据库并重启应用，健康/业务入口由 200 变 502，ATR 真实 Collector 读取下分别 unresolved、零模型调用、各 7 工具；恢复后健康/业务均 200。实际失败的停止容器进程读取保留 failed 审计，没有伪造成功。A 调查 14.125 秒、B 29.406 秒。完整记录 [Docker](verification/v22-docker-runtime.json)、[A/B](verification/v22-docker-demos.json)、[最终持久化](verification/v22-docker-final.json)。

**Linux/OpenSSH：** 隔离容器 UID/GID 10002，root 所有的策略/入口/只读资料、固定公钥、禁密码/转发/TTY、服务器 ForceCommand。实际拒绝任意命令/修改/非授权路径、穿越、链接、FIFO；550 无关进程的定向发现、分页、超时与断连通过；成功/拒绝/超时调用审计和脱敏通过。以该账号实际写打开配置被 PermissionError 拒绝，5 处资料/策略路径不可写。[SSH XML](verification/v22-linux-ssh.xml)、[权限](verification/v22-linux-permissions.json)。未接真实业务服务器。

**模型：** 实际 LiteLLM 对本地假 HTTP 服务的 5 项测试覆盖 JSON、usage、503/无效 JSON/超时、无重试、原子结算、token 网络前预检、单次/累计调用限制、脱敏与提示输入隔离。13/7 usage 为假服务回传的测试数值；调查 Stub 无 usage，记录保守估算；无费率时费用未知。**真实模型供应商尚未验证**，未自行搜寻 Key。
