## 实际隔离 Linux/OpenSSH 18 项

需要自己的可用 WSL Linux Docker Engine、可用 python:3.12-slim 基础镜像及 apt 网络。夹具不挂 Docker socket，不连接生产。550 个非特权 sleep 进程运行 900 秒，测试须在启动后及时执行。专用容器名及端口须未被其他资源使用；有冲突时给新夹具改名/改端口，同时修改测试 JSON。

先在项目目录的 PowerShell 生成全新的**夹具密钥**及配置，不使用真实服务器私钥。目录已存在时脚本拒绝覆盖；重跑改用新的目录名。

```powershell
@'
import json
from pathlib import Path
import paramiko

directory = Path("work/ssh-fixture-retest-01")
directory.mkdir(parents=True, exist_ok=False)
keys = {}
for name in ("host_key", "client_key"):
    key = paramiko.RSAKey.generate(2048)
    key.write_private_key_file(str(directory / name))
    keys[name] = key
(directory / "client.pub").write_text(
    keys["client_key"].get_name() + " " + keys["client_key"].get_base64() + "\n",
    encoding="utf-8",
)
config = {
    "config": {
        "name": "isolated Linux fixture", "connector": "ssh",
        "host": "127.0.0.1", "port": 32022, "username": "atrreader",
        "credential_ref": "v22-fixture",
        "host_public_key": keys["host_key"].get_name() + " " + keys["host_key"].get_base64(),
        "allowed_paths": ["/srv/atr-fixture"], "access_authorized": True,
        "permission_boundary": "forced_command_gateway",
        "boundary_attestation": "Dedicated local fixture: root policy, non-root reader, ForceCommand, read-only paths.",
        "timeout_seconds": 3, "max_output_bytes": 48000,
    },
    "key_path": str((directory / "client_key").resolve()),
}
(directory / "ssh-config.json").write_text(json.dumps(config), encoding="utf-8")
print("Created local fixture keys and configuration; no key contents printed.")
'@ | .venv/Scripts/python.exe -
```

在 WSL 终端进入**同一项目目录**的 /mnt/... 路径，确认是自己的隔离 Engine 后构建/启动：

```sh
docker build -f tests/fixtures/linux-ssh/Dockerfile -t atr-v22-ssh-retest .
docker run -d --name atr-v22-ssh-retest \
  --label atr.v22.validation=ssh-retest \
  --pids-limit 700 --memory 512m --cpus 2 \
  --security-opt no-new-privileges:true \
  -p 127.0.0.1:32022:2222 -p 127.0.0.1:32023:2223 -p 127.0.0.1:32024:2224 \
  -v "$(pwd)/work/ssh-fixture-retest-01:/keys:ro" atr-v22-ssh-retest
```

SSHD 主进程需 root 初始化，实际调查账号 UID/GID 10002；root 所有策略/入口、固定公钥和目录权限共同约束读取，不能仅凭客户端白名单认定只读。启动后在 Windows PowerShell 执行：

```powershell
$env:ATR_LINUX_SSH_CONFIG = (Resolve-Path work/ssh-fixture-retest-01/ssh-config.json).Path
.venv/Scripts/python.exe -m pytest tests/integration/linux_ssh_acceptance.py -q --basetemp=test-results/tmp-ssh-repeat01 --junitxml=test-results/ssh-repeat01.xml
```

在 WSL 终端额外检查服务器实际写权限：

```sh
docker exec -i --user 10002:10002 atr-v22-ssh-retest python3 - < tests/fixtures/linux-ssh/check_permissions.py
docker inspect --format '{{ index .Config.Labels "atr.v22.validation" }}' atr-v22-ssh-retest
docker stop atr-v22-ssh-retest
```

停止前确认标签为 ssh-retest。停止不删除配置、测试记录或 Volume。上述为已验证夹具的重跑步骤；目标机器镜像获取、WSL 端口转发和目录映射仍需自行确认。

## 故障三臂比较

锁定开发环境和自己的 WSL Ubuntu Engine 准备完成后，在项目 PowerShell 执行；替换为自己实际的发行版名及全新输出路径：

```powershell
.venv/Scripts/python.exe scripts/evaluate_faults.py --docker-wsl Ubuntu --allow-isolated-mutations --repetitions 2 --work-dir work/evaluation-repeat01 --output test-results/evaluation-repeat01.json
```

13 个案例各两次 × 三模式，共 78 次 API/SQLite/Gate 调查。脚本拒绝覆盖已有评测数据库；仅注入带 atr.v22.evaluation=isolated 标签的新专用容器，network=none、只读、非特权、资源受限。结束取样后移除这些无 Volume 的新容器。模型不读取标准真值，token 为预算估算、无费率则费用未知。store/cache/edge 为 Python TCP 替身；原真实 A/B 的数据库/Nginx 复验见 [Demo 手册](demo-runbook.md)。不加 Docker 参数可检查合成 Mock 流程，但该结果必须标为 Mock/Stub。

最终数据保存步骤、调用、原始日志时间、标准真值、权限范围与评分；比较只纳入完整三臂。当前机制覆盖较窄，未解决和部分诊断不算完整正确。此次结果见 [评测报告](v2.2-evaluation-report.md)。

## 实际 Docker UI 与持久化

先按 [部署](deployment.md) 启动自己的项目，检查上传 Worker、健康端点和 SQLite Volume。浏览器测试支持 ATR_E2E_BASE_URL 指向该隔离 UI，并用 ATR_E2E_OPERATOR_TOKEN 提供其操作者 token；token 只在进程内设置，不写报告或命令历史。端到端测试会创建新的测试业务和资料，不应对生产运行。本次用 28080 端口实际通过，并在替换 API 前后逐对象核对原画像、上传源和索引保留。

验证后停止自己启用的 Docker Collector，保留数据库/Volume/上传/历史。API/UI 可继续用于本地查看。真实供应商模型需操作者明确启用并提供自己的凭据；本次未执行，不能把本地假 HTTP usage 或 Stub token 估算称为实际模型账单。
