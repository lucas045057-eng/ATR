# ATR V2.2 增量设计

目标是授权范围内的多轮证据调查，并在证据不足时可靠停止。保留 FastAPI、SQLite、LangGraph、LiteLLM、React、业务画像、Context Budget、Evidence Gate 和人工审核的 Trusted Pattern。无远端任意命令、自动修复、生产连接、数据清理或远端 Git 发布。

## 工程修复

固定清单工具接受最多八条受 Schema 约束的名称线索和受限游标。网关使用固定参数的定向查询及流式限量解析，分别限制扫描、保留数据、耗时和调用数，返回 partial/truncated/timeout。候选排名不授权。

绑定审核状态与运行证据时效分开：原有人工确认用于授权，freshness_status、observed_at、expires_at、source_json、candidate_digest 用于当前事实。失败或不完整采样不能证明对象消失；完整新证据才能提示 stale/重新审核。迁移后的无来源旧绑定 unverified，不伪造观察时间。

调查任务在 SQLite BEGIN IMMEDIATE 内原子复用/创建；重复请求只返回同一活动任务。失败和重启保持任务、调查、调用与预算的终态和审计一致。继续单 API 进程，不引入外部队列。

## 自适应调查

增加独立 Adaptive Planner 模块，动态维护最多三个活动假设并保留被推翻的历史。每轮从已授权服务、依赖、状态、限定日志、具体配置和源码检索生成有界候选；依假设区分度、相关性、新信息、成本、重复和权限评分排序，模型只选择候选标识，Policy 独立校验。

先进行低成本运行观察，之后 Observe → Hypothesize → Select → Policy → Execute → Evaluate → Replan。无新增行动、权限阻塞、冲突、预算或轮数耗尽均显式停止。未授权依赖只形成申请，不能执行。历史 Pattern 仅提供建议。

## 因果验证

保留原 Gate 的全部最低约束；增加确定性预测可行性、机制与当前故障信号匹配、事件时间关联、来源独立性及未由模型报告的反证检查。普通 ERROR 和静态代码不能证明实时根因；模型置信度不授权 supported。识别到的现象与可能机制分别输出，无法验证的机制 unresolved。存储每轮假设/预测/反证。

## 验收与知识

按阶段执行且保存实际结果。先基线与 P0，再 Planner、Gate、隔离 Docker/Linux、故障评测、知识反馈和全量回归。真实模型仅在明确启用且有有效凭据时运行，否则 Stub 并标记未真实验证。评测记录真实执行次数/usage/工具/时间，不预填成功率；隔离夹具与生产事实明确区分。

经验检查顺序与失败反例增量保存，兼容性与效果反馈不自动提升 Trusted。保留修复事实、健康验证、人工审核的原晋升流程。
